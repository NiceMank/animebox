PROMPT 13 — IMPLÉMENTATION DE L’ONBOARDING ANIMEBOX

L’onboarding d’AnimeBox n’est pas encore implémenté.

Tu dois maintenant créer et intégrer l’onboarding complet de l’application en respectant STRICTEMENT l’identité visuelle déjà présente dans le projet et les maquettes existantes.

IMPORTANT :
- Ne modifie pas inutilement les écrans déjà terminés.
- Ne refais pas le design général de l’application.
- Ne crée pas une interface générique de type application de streaming.
- N’utilise AUCUNE donnée fictive.
- Aucun backend.
- Aucun serveur Vercel.
- Aucun serveur Python.
- Tout doit fonctionner localement sur Android.
- NE PAS utiliser d’emoji comme icônes.
- NE PAS utiliser des icônes génériques incohérentes avec le reste de l’application.
- Utiliser la même bibliothèque d’icônes professionnelle déjà utilisée dans le projet ou des SVG cohérents avec le design existant.

════════════════════════════════════
1. STRUCTURE DE L’ONBOARDING
════════════════════════════════════

L’onboarding doit contenir EXACTEMENT 3 écrans.

ÉCRAN 1
Titre :
« Bienvenue sur AnimeBox »

Présenter clairement AnimeBox et son objectif :
permettre à l’utilisateur de retrouver et organiser ses animés provenant de ses propres sources Telegram.

ÉCRAN 2
Titre :
« Tous vos animés au même endroit »

Présenter le fonctionnement général :
AnimeBox analyse les sources Telegram configurées par l’utilisateur et organise automatiquement les contenus en animés, saisons et épisodes.

ÉCRAN 3
Titre :
« Sécurisé & 100 % privé »

Expliquer simplement que :
- le compte Telegram appartient à l’utilisateur ;
- ses sources lui appartiennent ;
- les données de l’application sont conservées localement autant que possible ;
- AnimeBox ne nécessite pas de serveur central pour fonctionner.

Le troisième écran doit obligatoirement contenir le bouton :

« Commencer »

════════════════════════════════════
2. NAVIGATION
════════════════════════════════════

Écran 1 :
bouton « Suivant »

Écran 2 :
bouton « Suivant »

Écran 3 :
bouton principal « Commencer »

Ajouter un indicateur de progression permettant de voir clairement qu’il y a 3 étapes.

La navigation doit être fluide.

Utiliser des animations légères et professionnelles :
- transitions entre les pages ;
- apparition douce du contenu ;
- animation discrète des éléments visuels si cela correspond aux maquettes.

Éviter les animations excessives.

════════════════════════════════════
3. DESIGN
════════════════════════════════════

Respecter EXACTEMENT autant que possible le langage visuel déjà utilisé dans AnimeBox :

- thème sombre ;
- accents violets déjà présents ;
- typographie existante ;
- rayons des éléments déjà utilisés ;
- espacements cohérents ;
- animations existantes ;
- style des boutons existants ;
- iconographie existante.

L’onboarding doit donner l’impression d’avoir été conçu en même temps que le reste de l’application.

NE PAS introduire :
- cartes génériques ;
- gradients excessifs ;
- glassmorphism ;
- interface Android par défaut ;
- composants Material génériques qui cassent le design ;
- illustrations IA génériques sans cohérence avec AnimeBox.

Si les maquettes/images de l’onboarding sont déjà présentes dans le projet, elles sont PRIORITAIRES :
reproduis leur composition, leurs proportions, leurs textes, leurs positions et leur hiérarchie visuelle le plus fidèlement possible.

════════════════════════════════════
4. PREMIER LANCEMENT
════════════════════════════════════

L’onboarding doit apparaître uniquement lors de la première ouverture de l’application.

Créer une préférence locale permettant de mémoriser que l’utilisateur a terminé l’onboarding.

Exemple logique :

firstLaunch = true
→ afficher onboarding

Utilisateur appuie sur « Commencer »
→ enregistrer onboardingCompleted = true
→ ouvrir le parcours normal de connexion/configuration Telegram.

Lors des ouvertures suivantes :

onboardingCompleted = true
→ ne plus afficher l’onboarding
→ ouvrir directement l’application.

Cette préférence doit rester conservée après fermeture et redémarrage de l’application.

════════════════════════════════════
5. BOUTON « COMMENCER »
════════════════════════════════════

Le bouton « Commencer » ne doit PAS simplement fermer l’onboarding.

Il doit réellement lancer le parcours prévu dans l’application.

Après avoir terminé l’onboarding :

→ rediriger vers l’écran de connexion/configuration Telegram approprié déjà implémenté.

Ne crée pas un nouvel écran Telegram si un écran fonctionnel existe déjà.

Réutilise le flow Telegram existant.

Si un compte Telegram est déjà configuré, respecter la logique existante de l’application et ne pas forcer inutilement une nouvelle connexion.

════════════════════════════════════
6. RESPONSIVE
════════════════════════════════════

L’onboarding doit fonctionner correctement sur les différents formats d’écrans Android.

Vérifier notamment :
- petits écrans ;
- grands écrans ;
- différentes résolutions ;
- différentes densités ;
- mode portrait.

Aucun texte ne doit être coupé.

Aucun bouton ne doit sortir de l’écran.

Aucun élément ne doit être masqué par la barre système Android.

Gérer correctement les Safe Areas.

════════════════════════════════════
7. ARCHITECTURE
════════════════════════════════════

Respecter l’architecture Flutter déjà présente dans le projet.

Créer des composants propres et réutilisables.

Éviter de mettre toute la logique dans un seul fichier.

La logique de persistance de l’état de l’onboarding doit être séparée de l’UI si l’architecture actuelle le permet.

Réutiliser les services/preferences déjà présents dans le projet plutôt que créer une deuxième solution de stockage inutile.
